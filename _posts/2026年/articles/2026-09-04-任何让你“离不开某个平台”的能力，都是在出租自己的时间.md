最近被现实上了一课。

我的两个 Claude 账号都被封了；今天，OpenAI Plus 账号也没能幸免。

这件事让我意识到一个越来越明显的问题：**把所有工作流都押在别人的平台上，是有风险的。**

具体来说，有两个困境越来越突出：

- **额度的天花板。** OpenAI 送的那一点 Codex 额度，其实压根儿不够用。每 5 小时一小刷新，每 7 天一次大刷新，稍微用猛一点就断档。
- **账号的不确定性。** 哪怕你一直很规矩，平台一旦封号，你之前的所有脚本、配置、习惯，瞬间全部归零。

也就是说，哪怕你已经很熟练地用 CLI 做事，只要底层出问题，效率立刻回到原始状态。

那有没有更稳的方案？

我最近试了一下本地部署这条路：**Ollama + 本地模型**。

这条路的好处很直接：

- 不需要额度，不需要登录，断网也能用
- 数据都在自己手里，隐私不外泄
- 一次配置，长期使用，不受任何平台政策影响

虽然本地模型和云端顶级模型之间还有差距，但对日常润色、修改文件、自动化任务来说，**够用了**。

下面把我这一次的完整步骤记下来：

1. 进入 [ai-cli-kickstarter](https://github.com/xiaolai/ai-cli-kickstarter)，把整个文件夹下载下来。
2. 双击运行按钮，在命令行内安装 Qwen Code。
3. 下载 [Ollama](https://ollama.com)。
4. 打开 PowerShell，输入 `ollama`，按提示选择模型，我选了本地模型 `gemma3:27b`。
5. 配置 API key：在浏览器里登录账户，配置一个新的 API key。
6. 打开一个新的命令行窗口，输入 `qwen`。
7. 输入 `/model`，完成配置：
   - URL：`http://localhost:11434/v1`
   - API key：刚刚设置的那个

完成。

---

跑通之后，我最大的感受不是"省钱"，而是**拿回了一种久违的掌控感**。

过去一段时间，我的工作流几乎完全绑在几个云端 AI 上：CLI 要订阅、账号要保号、模型要更新。看起来很高效，但本质上，我是在用别人的规则、别人的服务器、别人的政策，安排自己的时间。

而本地部署之后，至少有一条线是完全属于我的：模型跑在我自己的机器上，速度由我的硬件决定，成本只算电费，不看任何人的脸色。

这件事给我一个更深的提醒：

> **任何让你"离不开某个外部平台"的能力，本质上都是在出租自己的时间。**

真正能留下来的，是那些哪怕离开某个平台，依然能跑下去的流程、习惯和积累。
